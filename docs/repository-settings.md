# Repository settings and controls

The baseline of both forges, for audits and for rebuilding the setup. Every control has
an id; `scripts/audit_repos.py` checks the live value of each automated control against
this baseline and prints PASS/FAIL (read-only tokens are enough):

```sh
GITLAB_TOKEN=... GITHUB_TOKEN=... python3 scripts/audit_repos.py
```

References used for the baseline: GitLab documentation (protected branches, merge request
settings, CI/CD job token, pipeline security), GitHub documentation (community profile,
rulesets, code security), the OpenSSF Scorecard checks and the OpenSSF Best Practices
criteria. Settings that need a paid tier are listed with the control that replaces them.

## 1. Roles of the two forges

| | GitLab.com (private) | GitHub (public) |
|---|---|---|
| Role | Source of truth: code, issues, merge requests, CI/CD, releases | Read-only mirror, public feedback (issues), security reporting |
| Who writes | The maintainer, through merge requests only | Only the GitLab push mirror (deploy key) |
| CI/CD | GitLab CI on two self-hosted ARM64 runners (NAS) | None (Actions only for CodeQL default setup) |

## 2. GitLab project

### Repository and merge requests

| Id | Control | Value | Why |
|---|---|---|---|
| GL-01 | Visibility | private | Work in progress stays private; the mirror publishes `main` only |
| GL-02 | Default branch | `main` | Trunk-based development |
| GL-41, GL-42 | `main` protected | push: no one, merge: maintainers, force push off | Every change goes through a reviewed, tested MR |
| GL-43 | Protected tags `v*` | create: maintainers | Releases cannot be forged |
| GL-03 | Merge method | fast-forward | Linear history: one commit per MR on `main` |
| GL-04 | Squash | always | The MR title becomes the commit; checked as a Conventional Commit in CI |
| GL-31 | Squash commit template | `%{title}` + `See merge request %{reference}` | Traceability from `main` back to the MR |
| GL-05, GL-06 | Pipeline must succeed, skipped pipelines refused | on | Nothing unverified reaches the public site |
| GL-07 | All threads resolved | on | Review comments cannot be ignored |
| GL-08 | Delete source branch | on | Short-lived branches |
| GL-28 | Auto-close referenced issues | on | `Closes #n` in an MR closes the issue |
| GL-29 | Warn about unwanted Unicode characters | on | Trojan-source style attacks |
| | Branch names | `feat/`, `fix/`, `chore/`, `docs/` | Enforced by `lint:commits` (push rules need Premium) |
| | Commit messages, MR title | Conventional Commits 1.0.0 | Enforced by `lint:commits` and the commit-msg hook |

### Templates

| Kind | Templates |
|---|---|
| Merge requests (`.gitlab/merge_request_templates/`) | Default, Protocol-page, Correction, Template-change, Release |
| Issues (`.gitlab/issue_templates/`) | New-protocol, Correction, Bug, Feature, Security (confidential), Release |
| Ownership | `.gitlab/CODEOWNERS` |

### Not available on GitLab Free, and what replaces it

| Premium/Ultimate feature | Replacement |
|---|---|
| Push rules (branch names, commit messages, reject unsigned commits) | `lint:commits` job and pre-commit commit-msg hook |
| Required approvals, code owner approval | Single maintainer; the pipeline and the Definition of done are the gate |
| Secret push protection | gitleaks in pre-commit and CI; GitHub push protection on the mirror |
| Dependency scanning | `security:dependencies` (weekly) and GitHub Dependabot alerts on the mirror |
| SAST dashboard | ruff with the flake8-bandit (`S`) rules; GitHub CodeQL on the mirror |
| Scoped (exclusive) labels | Same `key::value` names, one value per scope by convention |
| Audit events | `scripts/audit_repos.py`, history of this file |
| Default issue or MR description template | Templates named `Default` are selected automatically for MRs |

Known limitation: squash commits created by GitLab on merge are not signed, so GitHub shows
them as unverified. Branch protection, the MR gate and the deploy-key-only mirror are the
integrity controls.

## 3. GitHub mirror

| Id | Control | Value | Why |
|---|---|---|---|
| GH-01 | Visibility | public | Readers can audit the sources of every page |
| GH-02 | Pull requests | disabled (GitHub setting, February 2026) | Changes go through GitLab; nothing to review here |
| GH-03 | Issues | enabled, issue forms only (`blank_issues_enabled: false`) | Public feedback with a required source |
| GH-04 to GH-06 | Wiki, projects, discussions | off | One place for documentation and discussion |
| GH-07 | Homepage, description, topics (GH-33) | site URL, description, 18 topics | Discoverability |
| GH-21 | Branch ruleset `~ALL` | creation, update, deletion, force push blocked; linear history; bypass: deploy key only | Even the owner cannot push by mistake |
| GH-22 | Tag ruleset `~ALL` | same | Tags only from GitLab |
| GH-23 | Deploy keys | one: the GitLab push mirror, write | Single writer, revocable in one click |
| GH-24, GH-25 | Collaborators, webhooks | owner only, none | Least privilege |
| GH-20 | Owner 2FA | on | Account takeover |
| GH-26 | Private vulnerability reporting | on | Channel of `SECURITY.md` and `security.txt` |
| GH-27 | Dependabot alerts | on (security updates off: they would open pull requests) | Known-vulnerable pins in `requirements/*.txt` |
| GH-08, GH-09 | Secret scanning, push protection | on | Leaked credentials |
| GH-28 | CodeQL default setup | Python, extended queries | SAST on every mirrored commit |
| GH-29, GH-30 | Actions | GitHub-owned actions only, SHA pinning required, read-only token | Only CodeQL runs; no third-party code |
| GH-31 | Interaction limits | none (set only temporarily against spam) | Anyone may open an issue |
| GH-32 | Community profile | 100 % | README, code of conduct, contributing, licence, security, issue forms, PR template |
| GH-34 | Labels | same 41 labels as GitLab | One taxonomy |
| GH-35 to GH-37 | Open alerts | none | Zero known issue |

Community files read by GitHub: `README.md`, `LICENSE`, `CODE_OF_CONDUCT.md`,
`CONTRIBUTING.md`, `SECURITY.md`, `.github/SUPPORT.md`, `.github/ISSUE_TEMPLATE/`
(Correction, New protocol, Site problem, Improvement, `config.yml`),
`.github/pull_request_template.md` (explains that PRs go to GitLab), `CITATION.cff`.

## 4. Repository content controls

| Control | Where |
|---|---|
| Licences: MIT code, CC BY-SA 4.0 content, Cisco icons own terms; REUSE 3.3 | `LICENSE`, `LICENSES/`, `REUSE.toml`, `lint:reuse` |
| Security policy, response targets, `security.txt` (RFC 9116) | `SECURITY.md`, `scripts/build_site.py` |
| No secrets, captures or real addresses | `.gitignore`, gitleaks, `CLAUDE.md` Confidentiality |
| Pages self-contained, 4 languages complete, packets equal to the builder | `scripts/check_pages.py` |
| HTML valid, links and anchors, protocol index | `scripts/check_site.py` (`verify:site`) |
| WCAG 2.2 AA (light, dark, mobile), CLS, reduced motion, no external request | `scripts/smoke_test.py` (`verify:browser`) |
| Outdated pins | `scripts/check_updates.py` (`security:dependencies`) |
| SBOM of the build tooling (CycloneDX) | `build:sbom`, linked from each release |
| Release notes from the changelog | `scripts/create_release.py`, `CHANGELOG.md` |
| Decisions and their reasons | `docs/adr/` |
