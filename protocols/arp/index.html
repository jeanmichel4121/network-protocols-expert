1.1 Le problème : je connais l'adresse IP, il me faut une adresse MAC1.1 The problem: I know the IP address, I need a MAC address1.1 Het probleem: ik ken het IP-adres, ik heb een MAC-adres nodig1.1 Das Problem: Ich kenne die IP-Adresse, ich brauche eine MAC-Adresse

Une machine qui veut envoyer un paquet IPv4 connaît son destinataire par son adresse IP. Mais sur Ethernet, une trame est remise d'après une adresse MAC : les six premiers octets de la trame doivent contenir l'adresse MAC de la prochaine machine sur le lien. Rien dans l'adresse IP ne permet de la deviner : ce sont deux numéros sans rapport entre eux.[1]A host that wants to send an IPv4 packet knows its recipient by IP address. But on Ethernet a frame is delivered by MAC address: the first six bytes of the frame must hold the MAC address of the next machine on the link. Nothing in the IP address lets you guess it: the two are unrelated numbers.[1]Een host die een IPv4-pakket wil versturen, kent de ontvanger aan zijn IP-adres. Maar op Ethernet wordt een frame afgeleverd op basis van een MAC-adres: de eerste zes bytes van het frame moeten het MAC-adres van de volgende machine op de link bevatten. Niets in het IP-adres laat toe dat te raden: het zijn twee getallen zonder verband.[1]Ein Host, der ein IPv4-Paket senden will, kennt den Empfänger über dessen IP-Adresse. Auf Ethernet wird ein Rahmen aber anhand einer MAC-Adresse zugestellt: Die ersten sechs Byte des Rahmens müssen die MAC-Adresse der nächsten Maschine auf dem Link enthalten. Aus der IP-Adresse lässt sie sich nicht ableiten: Es sind zwei Nummern ohne Zusammenhang.[1]

ARP (Address Resolution Protocol) comble ce manque. Avant d'envoyer le premier paquet, la machine pose une question au réseau local : qui possède cette adresse IP ? Le propriétaire répond avec son adresse MAC. La machine note la paire dans une table, le cache ARP, et la trame peut partir.ARP (Address Resolution Protocol) fills this gap. Before sending the first packet, the host asks the local network one question: who owns this IP address? The owner answers with its MAC address. The host writes the pair in a table, the ARP cache, and the frame can leave.ARP (Address Resolution Protocol) vult dit gat. Voordat het eerste pakket vertrekt, stelt de host het lokale netwerk één vraag: wie bezit dit IP-adres? De eigenaar antwoordt met zijn MAC-adres. De host noteert het paar in een tabel, de ARP-cache, en het frame kan vertrekken.ARP (Address Resolution Protocol) schließt diese Lücke. Vor dem ersten Paket stellt der Host dem lokalen Netz eine Frage: Wem gehört diese IP-Adresse? Der Besitzer antwortet mit seiner MAC-Adresse. Der Host trägt das Paar in eine Tabelle ein, den ARP-Cache, und der Rahmen kann gesendet werden.

1.3 Où se place ARP : entre la couche 2 et la couche 31.3 Where ARP sits: between layer 2 and layer 31.3 Waar ARP zit: tussen laag 2 en laag 31.3 Wo ARP liegt: zwischen Schicht 2 und Schicht 3

Un paquet ARP n'est pas un paquet IP. Il est posé directement dans la trame Ethernet, avec son propre EtherType, 0x0806, à côté d'IPv4 (0x0800).[16] Il travaille pour la couche 3, mais il est transporté par la couche 2 : la RFC 1122 le range dans la couche lien.[4]An ARP packet is not an IP packet. It sits directly in the Ethernet frame, with its own EtherType, 0x0806, next to IPv4 (0x0800).[16] It works for layer 3 but is carried by layer 2: RFC 1122 files it under the link layer.[4]Een ARP-pakket is geen IP-pakket. Het zit rechtstreeks in het Ethernet-frame, met een eigen EtherType, 0x0806, naast IPv4 (0x0800).[16] Het werkt voor laag 3 maar wordt door laag 2 vervoerd: RFC 1122 deelt het in bij de linklaag.[4]Ein ARP-Paket ist kein IP-Paket. Es liegt direkt im Ethernet-Rahmen, mit eigenem EtherType 0x0806, neben IPv4 (0x0800).[16] Es arbeitet für Schicht 3, wird aber von Schicht 2 transportiert: RFC 1122 ordnet es der Link-Schicht zu.[4]

Cette place a une conséquence directe : sans en-tête IP, un paquet ARP ne peut pas être routé. Un routeur ne le fait jamais passer d'un réseau à l'autre. La portée d'ARP est donc le domaine de broadcast, c'est-à-dire le VLAN. Pour joindre une machine d'un autre réseau, on ne résout pas son adresse : on résout celle de la passerelle (leçon 1.5).This position has a direct consequence: with no IP header, an ARP packet cannot be routed. A router never passes it from one network to another. The reach of ARP is therefore the broadcast domain, that is, the VLAN. To reach a machine on another network, you do not resolve its address: you resolve the gateway's (lesson 1.5).Die plaats heeft een direct gevolg: zonder IP-header kan een ARP-pakket niet gerouteerd worden. Een router laat het nooit van het ene netwerk naar het andere gaan. Het bereik van ARP is dus het broadcastdomein, dat wil zeggen het VLAN. Om een machine op een ander netwerk te bereiken, los je niet haar adres op, maar dat van de gateway (les 1.5).Diese Einordnung hat eine direkte Folge: Ohne IP-Header kann ein ARP-Paket nicht geroutet werden. Ein Router leitet es nie von einem Netz ins andere. Die Reichweite von ARP ist also die Broadcast-Domäne, das heißt das VLAN. Um eine Maschine in einem anderen Netz zu erreichen, löst man nicht deren Adresse auf, sondern die des Gateways (Lektion 1.5).

1.4 Le cache ARP : ne pas reposer la question à chaque paquet1.4 The ARP cache: not asking again for every packet1.4 De ARP-cache: niet bij elk pakket opnieuw vragen1.4 Der ARP-Cache: nicht bei jedem Paket neu fragen

Poser la question avant chaque paquet inonderait le réseau de broadcasts. Chaque machine garde donc les réponses dans une table, le cache ARP. Avant d'envoyer, elle y cherche l'adresse IP du prochain saut : si la paire s'y trouve, la trame part tout de suite ; sinon, ARP est lancé et le paquet attend.[1]Asking before every packet would flood the network with broadcasts. Each host therefore keeps the answers in a table, the ARP cache. Before sending, it looks up the IP address of the next hop: if the pair is there, the frame leaves at once; if not, ARP starts and the packet waits.[1]Vóór elk pakket vragen zou het netwerk overspoelen met broadcasts. Elke host bewaart de antwoorden daarom in een tabel, de ARP-cache. Vóór het verzenden zoekt hij er het IP-adres van de volgende hop in op: staat het paar erin, dan vertrekt het frame meteen; zo niet, dan start ARP en wacht het pakket.[1]Vor jedem Paket zu fragen würde das Netz mit Broadcasts fluten. Jeder Host behält die Antworten daher in einer Tabelle, dem ARP-Cache. Vor dem Senden sucht er dort die IP-Adresse des nächsten Hops: Ist das Paar vorhanden, geht der Rahmen sofort hinaus; sonst startet ARP und das Paket wartet.[1]

Une entrée ne doit pas rester pour toujours : une carte réseau peut être remplacée, une adresse IP peut changer de machine. La RFC 1122 impose donc un mécanisme pour éliminer les entrées périmées, et un délai réglable s'il s'agit d'une temporisation.[4] Elle impose aussi de ne pas répéter la même question à haut débit : au plus une par seconde et par destination est la valeur recommandée.An entry must not stay for ever: a network card can be replaced, an IP address can move to another machine. RFC 1122 therefore requires a mechanism to flush out-of-date entries, and a configurable value if it is a timeout.[4] It also requires not repeating the same question at a high rate: at most one per second per destination is the recommended value.Een regel mag niet eeuwig blijven: een netwerkkaart kan vervangen worden, een IP-adres kan naar een andere machine verhuizen. RFC 1122 eist daarom een mechanisme om verouderde regels te verwijderen, en een instelbare waarde als het om een time-out gaat.[4] Ze eist ook dat dezelfde vraag niet in hoog tempo herhaald wordt: hoogstens één per seconde per bestemming is de aanbevolen waarde.Ein Eintrag darf nicht ewig bleiben: Eine Netzwerkkarte kann getauscht werden, eine IP-Adresse kann auf eine andere Maschine wandern. RFC 1122 verlangt daher einen Mechanismus, der veraltete Einträge entfernt, und einen einstellbaren Wert, wenn es ein Timeout ist.[4] Außerdem darf dieselbe Frage nicht mit hoher Rate wiederholt werden: höchstens eine pro Sekunde und Ziel ist der empfohlene Wert.
